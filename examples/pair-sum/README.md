# オフライン練習問題：和が K になる組

AtCoder の実際の問題を転載したものではなく、この環境の操作を試すための例題です。

整数列 `A` と整数 `K` が与えられます。`i < j` かつ `A[i] + A[j] == K` を満たす添字の組の個数を出力します。同じ値でも添字が違えば別の組です。

```text
N K
A_1 A_2 ... A_N
```

- `main.py`：出現回数を数えて解く `O(N)` の解法。
- `brute.py`：すべての組を調べる `O(N²)` の参照解。
- `buggy.py`：値の重複を数え落とす、意図的に誤った実装。
- `cases.py`：Hypothesis の生成条件、境界ケース、ベンチマーク用入力。
- `test/`：入力と期待される出力の組。

リポジトリのルートから実行します。

```bash
ac test examples/pair-sum
ac stress examples/pair-sum
ac stress examples/pair-sum --solution 'python buggy.py'
```

最後のコマンドは WA の検出を体験するためのもので、終了コードが非ゼロになるのが正常です。例えば `K = 0, A = [0, 0, 0]` では正解は `3` ですが、`buggy.py` は `2` を出力します。縮小の結果は Hypothesis のバージョンや探索順に依存し、常に同じ最小入力になるとは限りません。

生成する制約は差分テスト用に小さくしています。`benchmark_case(size, seed)` はより大きな入力を作り、同じサイズと seed なら同じ結果を返します。ベンチマークで実行時間を測っても、AtCoder のジャッジ環境で同じ時間になるとは限りません。
